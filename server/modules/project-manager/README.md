# 项目管理插件（dsh-plugin-project-manager）

以**飞书多维表格为唯一数据源**的项目管理看板，配合**本机影刀**轮询执行指令，页面经后端聚合层（云函数）展示。

## 一、整体架构

```
飞书多维表格（项目主表 + 指令任务表，唯一数据源）
        ▲ 读 / 写回                      ▲ 读（经聚合层）
本机影刀（常开，定时轮询 → 顺序执行指令 → 回填结果与状态）
        ▲ 聚合展示
项目管理页面（看板 / 阶段进度 / 指令列表 / 专注模式 / 预览表格）
```

- **数据源**：飞书多维表格两张表，一对多（一个项目 → 多条指令）
- **执行**：本机影刀常开轮询指令表，同项目按排序号顺序执行，电脑常开保障轮询持续
- **展示**：页面经后端 `project-manager` 模块（聚合层）读取并组装，不直接读表
- **重执行**：失败 / 未执行 / 已完成的指令均可手动重跑（状态重置为「待执行」重新排队）

## 二、数据模型与字段约定

### 1. 项目主表（一行一个项目，table_id 填在连接配置的「项目主表」）

| 字段 | 类型 | 说明 |
|------|------|------|
| 项目名称 | 文本 | 如「本地媒体」 |
| 平台 | 单选 | 如豆包、微信、浏览器等 |
| 当前阶段 | 单选 | 固定四阶段：**立项 / 开始开发 / 完成 MVP / 完整功能上线** |
| 当前阶段进度 % | 数字 | 0-100，页面只展示这个百分比（方案 A，不做加权折算） |
| 注意事项 | 多行文本 | 支持 Markdown 编写；列表页折叠预览、展开渲染，详情页直接渲染 |
| 负责人 / 优先级 / 更新时间 | 可选 | 管理用，更新时间留空时页面显示「—」 |

> 字段名兼容：项目名称（也认「名称」「项目名」）、当前阶段进度 %（也认「当前阶段进度」「阶段进度」）、注意事项（也认「备注」）、当前阶段（也认「阶段」）。

### 2. 指令任务表（一行一条指令，关联所属项目）

| 字段 | 类型 | 说明 |
|------|------|------|
| 指令编号 / 名称 | 文本 | 便于识别 |
| 所属项目 | 关联记录 | 关联项目主表，实现一对多 |
| 平台 | 单选 | 豆包等 |
| 对话 / 指令内容 | 多行文本 | 如「新增选择媒体资源」，影刀原样发出 |
| 执行状态 | 单选 | **待执行 / 执行中 / 完成 / 失败** |
| 返回结果 | 多行文本 | 影刀回填豆包返回内容 |
| 错误信息 | 多行文本 | 失败原因 |
| 排序号 | 数字 | 决定同项目内执行先后 |
| 触发时间 / 完成时间 | 日期（时间戳） | 影刀领取时写触发时间，回填时写完成时间 |
| 影刀任务 ID | 文本 | 可选，日志与排障 |

> 字段名兼容：执行状态（也认「状态」）、返回结果（也认「结果」）、错误信息（也认「错误」）、排序号（也认「序号」）、指令编号 / 名称（也认「指令名称」「名称」）、对话 / 指令内容（也认「指令内容」「内容」）。

### 指令状态机

```
待执行 ──轮询捡到并加锁(claim)──▶ 执行中 ──成功(report)──▶ 完成
                                    └──失败/超时(report)──▶ 失败 ──手动重跑(rerun)──▶ 待执行
```

## 三、连接配置

页面右上角「连接配置」填写：

1. **app_token**：飞书多维表格链接 `https://xxx.feishu.cn/base/<app_token>?table=<table_id>` 中 `base/` 后的一段
2. **项目主表 table_id**（tbl 开头）
3. **指令任务表 table_id**（tbl 开头）
4. **API 凭证**（二选一）：
   - 个人令牌：飞书客户端「设置 → 安全设置 → 个人令牌」生成
   - 自建应用：飞书开放平台创建应用，开启「多维表格」权限，使用 App ID / App Secret（后端自动换取 tenant_access_token）
5. **表格预览链接**（可选）：填表链接，页面「打开表格」按钮直接跳转
6. **轮询间隔（分钟）**：仅展示参考，实际轮询由影刀侧配置

## 四、API 一览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/project-manager/overview` | 聚合看板（项目 + 阶段进度 + 指令 x/y） |
| GET | `/api/project-manager/projects/:recordId` | 项目详情（含指令列表，按排序号） |
| POST | `/api/project-manager/instructions/:recordId/rerun` | 重执行（任意状态 → 待执行，清空旧结果/错误） |
| POST | `/api/project-manager/instructions/:recordId/claim` | 影刀领取（待执行 → 执行中，写触发时间，加锁防重复） |
| POST | `/api/project-manager/instructions/:recordId/report` | 影刀回填（执行中 → 完成/失败，写结果/错误/完成时间） |
| GET | `/api/project-manager/config` | 读取连接配置（不回显令牌明文） |
| POST | `/api/project-manager/config` | 保存连接配置 |
| POST | `/api/project-manager/config/test` | 测试连接（可用未保存的配置试连） |

所有接口需登录（Bearer token，与系统其他 API 一致）。AI 对话也可直接使用 `project-manager.getOverview` / `getProject` / `rerunInstruction` / `getConfig` / `updateConfig` 方法。

## 五、影刀对接（本机轮询）

影刀脚本建议流程（电脑常开）：

1. **轮询**：按配置间隔拉取指令表，筛 `执行状态 = 待执行` 的记录，按项目分组、组内按排序号排序
2. **领取**：对下一条要执行的记录调用 `POST /api/project-manager/instructions/{recordId}/claim`（服务端校验状态并加锁；状态不是「待执行」会拒绝，避免重复触发）
3. **执行**：打开豆包 → 按项目名定位对应会话 → 原样发送「对话 / 指令内容」→ 等待并抓取返回文本
4. **回填**：成功调 `POST .../report`（status=完成 + result）；失败调 `POST .../report`（status=失败 + error），服务端记完成时间
5. **重跑**：失败 / 未执行项由页面或 AI 调 `rerun` 重置为「待执行」，下一轮轮询自动捡起

> 影刀也可直接读写飞书表（不经过本插件 API），页面聚合层会自动读到最新状态；两种方式可混用，但**同一时刻只能有一个执行者领取指令**（claim 状态机保证）。

## 六、页面功能

- **看板卡片**：项目名、平台、当前阶段、当前阶段百分比进度条、注意事项（折叠/展开，支持 Markdown）、指令完成 x/y（执行中 N 标蓝脉冲、失败数标红）、更新时间
- **筛选 / 搜索 / 排序**：按平台、阶段、指令状态（存在该状态的指令）筛选；关键词搜索项目名/注意事项/指令内容；按更新时间 / 阶段进度 / 名称排序
- **四阶段步骤条**：立项 → 开始开发 → 完成 MVP → 完整功能上线；已完成打勾、当前阶段高亮并显示 0-100% 进度、未开始灰显（方案 A）
- **项目详情 / 指令列表**：每条指令显示对话内容、状态、返回结果、错误、排队顺序（排序号）、时间；提供「重新执行」；顶部「指令列表」按钮一键跳转到列表区域
- **专注模式**：点击项目进入聚焦，隐藏其他项目；支持返回看板
- **打开表格**：跳转飞书多维表格管理（编辑以原表为准）
- **连接配置**：配置 / 测试连接，未配置时页面展示字段约定引导
